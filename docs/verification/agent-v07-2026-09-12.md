## Isolated live workflow

`test-v07-live.mjs` runs only against an explicitly named debug verification root. Its database, Brain, captures, receipt store and socket are separate from the installed app. The only recorded window is the synthetic verification window, with microphone and system audio off.

Verified:

1. Live action discovery reports the running app and new actions.
2. Import, wait for OCR/indexing, select a measured word region, and save a marked-up copy.
3. Compare original versus marked-up images; an ignored whole-image region reports zero compared and changed pixels.
4. Wait for the current revision's Brain export and an existing job. Inapplicable stages fail explicitly.
5. A real local MCP client creates a note and requests a screenshot comparison through the packaged app server.
6. Generate an OpenType font; request quality for intended text; inspect an actual-font specimen and recapture recommendations.
7. Start a five-second recording of the fixture window, wait for finalization and receive full attachment metadata.
8. Export a new MP4 with a title, numbered step, caption, zoom and opaque redaction; inspect an eight-frame contact sheet.
9. The packaged CLI executable exercises readiness, comparison, font quality and video export; synthetic artifacts are deleted through the normal lifecycle afterward.

The smoke tests exposed a missing indexing worker in the debug harness and missing attachment enrichment in recording waits. Both were corrected. Two harness assumptions about existing response shapes (window arrays and recording receipts) were corrected before the final passing run.

## Limits and host verification

- Word targeting uses Vision token boxes, not arbitrary visual-object or UI selectors. Duplicate matches remain explicit ambiguity errors.
- Comparisons require equal image dimensions. Ignore regions affect analysis and are not secure redaction. OCR differences are evidence, not functional assertions.
- Video zooms use explicit fixed regions. Title cards replace frames without changing duration. Redaction covers specified visual regions/times only; it does not remove audio.
- Transcript/notes readiness waits for available text. A silent or failed processing result can time out instead of falsely claiming completion. Waiting never starts/retries processing.
- Font evidence reports are heuristics, not exact identification or fidelity guarantees.
- No GrokBot execution tool is available here. Host discovery, Mac selection and attachment delivery through GrokBot are **not verified**. A complete acceptance recipe is in `docs/agent-workflows.md`.
- Candidate 0.7.0 is prepared, not submitted or approved. The initial Cursor publisher application remains pending. No marketplace email or form was sent.
